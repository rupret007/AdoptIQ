AdoptIQ Operator Guide

How to run AdoptIQ, choose the right report, configure the app, and fix common issues.

Quick Start (60 seconds)

AdoptIQ is a desktop app. You launch it, it opens in your browser, you run a report, and you find the file. That's the whole loop.

1
Connect to the Cisco VPN. AdoptIQ reads from Snowflake and Cisco internal services. Without VPN, data fetches fail.
2
Launch AdoptIQ. Double-click the app icon. It opens http://localhost:5151 in your default browser automatically.
3
Pick a manager, a technology, and a time window, then choose a report type and click run. Progress shows live.
4
Download the Word + Excel files from the results page, or find them later under History / Previous Reports.
5
Quit cleanly with the red Quit button in the navbar when you're done. This stops the local server and releases the port.
No setup required. Credentials are bundled into the app at build time. You do not edit any .env file or install packages — just connect to VPN and launch.
Which Report Should I Run?

Every report takes the same three inputs — Manager, Technology (or "All Contact Center" / "All Technologies"), and a time window in days (1–365). They differ in scope and audience.

Comprehensive

The full portfolio deep-dive: per-customer storyboards, risk components, adoption barriers, action plans, BE-priority focus areas. Best for a complete account review. Word + multi-sheet Excel.

Compact

An executive-length summary of the same portfolio: top customers, risk scores, key barriers. Best for a leadership readout when you don't need every customer's detail.

Renewal Risk

Focuses on renewal exposure and per-customer risk scoring (0–10). Available for a single customer (search a subscription) or a whole portfolio. Best when the question is "what's at risk this renewal?"

Leader

Scoped by CSSM ownership across a manager's direct reports: action plans, barriers, pulse, TAC cases per CSSM. Best for a people-manager reviewing their team's book of work.

Time window guidance: 30–60 days for a quick review, 90 days for a standard analysis, 180 days for a deep trend dive. Start broad ("All Contact Center" / "All Technologies") and drill into a named technology if you need to.
Where the Data Comes From (CSOne & OneDrive)

AdoptIQ blends live Snowflake data with a CSOne adoption-barrier export (an .xlsx from CSConsole). There are three ways AdoptIQ finds that CSOne file, in priority order:

  1. Manual upload. On the analyze page, browse and select your latest CSOne .xlsx (.xlsx/.xls, under 50 MB). This always wins when you provide it.
  2. OneDrive autodiscovery. If you don't upload one, AdoptIQ looks in your synced OneDrive corpus folder and picks the most recent AdoptIQ CSOne export automatically. Zero-byte "Files-On-Demand" placeholders are skipped (they aren't really on disk yet).
  3. Preferences folder override. If your local sync path doesn't match the canonical shape, set an explicit folder in Preferences → CSOne OneDrive folder and AdoptIQ uses that path directly.
If AdoptIQ can't find a CSOne file at all, adoption-barrier sheets will be empty and the report will carry a partial-data warning. Upload a file or fix your OneDrive sync to resolve it.

Generate the CSOne export yourself

If the shared export is stale or you want fresh data, generate the .xlsx directly from CSOne:

  1. {% if csone_report_url %} Open the CSOne report: AdoptIQ Export (CSOne) {% else %} Open the CSOne AdoptIQ Export report. {% endif %}
  2. Click the dropdown (▾) at the top-right of the report.
  3. Click Export.
  4. Choose Standard → Excel (.xlsx).
  5. Return to the analyze (or leader report) page and browse to upload the downloaded .xlsx.
Preferences Hub

The Preferences page is where you tune AdoptIQ. Every setting persists to a private settings.json (mode 0600, never committed) and takes effect on the very next run — no restart needed.

Report model

The LLM used for report narratives. Defaults to gemini-3.1-flash-lite. You can switch to gpt-5-nano from the dropdown. Test-before-Save: the Save button stays disabled until you click Test and the model responds OK.

Ask AI model

The LLM used by the Ask AI feature, independent of the report model. Same default (gemini-3.1-flash-lite) and the same Test-before-Save gate.

Corpus share URL

The SharePoint share link AdoptIQ points operators at to add the knowledge-corpus folder to their OneDrive. Paste, Test, Save, or Clear to fall back to the built-in default.

CSOne OneDrive folder

An explicit local path to your synced CSOne folder, for when autodiscovery can't match your sharer-prefixed sync path. Overrides autodiscovery when set.

Output folder

Where generated reports are written. Defaults to ~/Documents/AdoptIQ Reports on packaged builds. Reports are grouped by <manager>/<report type>/.

Default scope

Pre-select your usual manager / technology / days so the analyze form opens ready to run. Plus the Intelligence on/off toggle (see next section).

AdoptIQ Intelligence & Knowledge Corpus

AdoptIQ Intelligence powers the Ask AI feature and historical-context grounding by indexing prior AdoptIQ reports into an encrypted local knowledge corpus.

Pre-baked corpus

Every release ships with a pre-baked, encrypted corpus bundled into the app. On first launch it installs to your Application Support folder, so Ask AI works out of the box without waiting for an index pass.

"Add shortcut to OneDrive" workflow

To get daily refreshes of the corpus from the latest team reports, you add the shared corpus folder to your own OneDrive:

  1. Open the AdoptIQ corpus folder in SharePoint (use the deep link on the Intelligence panel / Preferences).
  2. Click "Add shortcut to OneDrive."
  3. Let the OneDrive desktop client sync it. AdoptIQ detects the synced folder and unblocks daily refresh.
Security: the corpus is encrypted at rest (AES-256-GCM). The encryption key is derived from a sentinel in your synced OneDrive folder, so only authorized Cisco users with the shared folder can decrypt it. The share URL is not a secret — OneDrive/SharePoint access is the gate. While running, AdoptIQ holds a single-user plaintext copy in a temp file that is scrubbed on clean Quit.
Ask AI

Ask AI answers natural-language questions about a manager's portfolio, grounded in retrieved evidence so it cites its sources instead of guessing.

  • Context: pick a manager/scope; Ask AI retrieves the most relevant evidence (hybrid BM25 + dense retrieval) and builds the answer from it.
  • Citations: answers carry [Source: ID] badges. Click a badge to see the snippet, source type, customer, and timestamp behind the claim.
  • Conversation mode: follow-up questions keep the prior context so you can drill in without re-stating the portfolio each time.
  • Limitations: Ask AI only knows what's in the corpus + the live portfolio briefing. For portfolios over 500 customers it streams a bounded sample and flags that per-customer metrics are unavailable for that run. It never fabricates numbers — ungrounded figures are rejected by the narrative validator.
Tip: if Ask AI says data is unavailable, check that VPN is up and the Intelligence panel shows the corpus as Active.
External Intelligence

The External Intelligence page layers in public service-health context: Webex status incidents, maintenance windows, and known bugs from status.webex.com / help.webex.com.

  • Refresh pulls the latest incidents/bugs/maintenances into the local store.
  • Ask / query the stored intel to correlate an outage with a customer's reported barriers.
  • Export / Import the intel store to share a snapshot with a teammate offline.
Finding Your Reports
On disk

Reports land in your output folder, grouped as <Output>/<Manager>/<Report Type>/. Per-customer reports go under <Manager>/Customer/<Customer>/. Default output root is ~/Documents/AdoptIQ Reports.

In the app

Use History and Previous Reports in the navbar to browse and re-download past runs without hunting through the filesystem.

Every report carries a Build Label (Word footer / Excel Report_Info sheet) with App_Version, App_Build, and UTC timestamps so you can prove exactly which build produced a file.
Admin Console & Diagnostics

The Admin Console link in the navbar opens a separate monitoring dashboard (loopback only) in a new tab. It is a plain link — it never shuts the server down. Only the red Quit button stops AdoptIQ.

  • Watch currently-running reports, phase timings, and grounding-rejection rates.
  • Inspect connection telemetry, error logs, audits, and analytics.
  • Run the same connectivity self-test available below.
Troubleshooting
Common Issues & Solutions
VPN not connected

Symptom: Data fetches time out, "Connection failed", or reports come back empty.

Solution: Connect to the Cisco VPN before running anything. AdoptIQ reads from Snowflake and Cisco internal services that are only reachable on the corporate network. Re-run after the VPN is up.

Database Connection Issues

Symptom: "Connection failed", "Keeper Connection Error", or timeout errors

Solution: Confirm VPN is up, then run the connectivity self-test below to pinpoint which step (DNS, TLS, AppRole, secret-read, Snowflake) is failing.

File Upload Problems

Symptom: Upload fails or file not recognized

Solution: Ensure file is .xlsx/.xls format and under 50MB

OneDrive not synced

Symptom: The Intelligence panel shows "not synced", or CSOne autodiscovery finds nothing.

Solution: Add the corpus folder to your OneDrive ("Add shortcut to OneDrive") and let the desktop client finish syncing. If your local path is non-standard, set it explicitly in Preferences → CSOne OneDrive folder.

Partial-data warnings

Symptom: A report banner / Report_Info sheet notes missing CSOne, empty scope, or excluded rows.

Solution: This is honest disclosure, not a crash — the report was still produced. Upload a fresh CSOne export, widen the scope (e.g. "All Contact Center"), or accept the noted gap. Excluded-row counts tell you exactly what was dropped.

Restart-required banner

Symptom: A yellow banner says a newer AdoptIQ build is on disk than the running process.

Solution: Click the red Quit button, then relaunch the app. Reports generated after the restart carry the new App_Build in their Build Label.

Quit & Force-quit

Symptom: Clicking Quit while an analysis is running shows a confirmation prompt instead of stopping.

Solution: That's the safety gate — it refuses to kill in-flight work unless you confirm with Force quit. The clean-quit path also flushes your run history and scrubs the in-memory corpus, so always prefer Quit over force-closing the app.

Analysis Failures

Symptom: Analysis stops or produces errors

Solution: Open the Admin Console to read error logs and per-run diagnostics. Most failures trace back to VPN, OneDrive sync, or a stale CSOne file.

Advanced: Build Provenance & Model Selection
Build Label on Every Report (Round 68)

Every Word and Excel report generated by AdoptIQ carries a Build Label footer (Word) or Report_Info sheet (Excel) showing the exact app version, build number, and timestamps:

  • App_Version -- e.g. 1.0.4 from config.py
  • App_Build -- e.g. 45 from config.py
  • Process_Started_At_UTC -- when the analysis worker was launched
  • Report_Generated_At_UTC -- when the report file itself was written

Use these fields to reproduce a report exactly: regenerate from the same CSOne snapshot using the same app build to get the same numbers. If you ever see drift between two reports labelled with the same App_Build, that is a regression worth reporting.

Restart-After-Update Banner (Round 68)

When you replace the AdoptIQ binary while the app is running, a yellow banner appears at the top of the analyze page warning that the running process is on an older build than the one on disk. Click Quit AdoptIQ in the navbar, then relaunch the app to pick up the new build. Reports generated after the restart will carry the new App_Build value in their footer / Report_Info sheet.

LLM Model Preferences (Round 69)

AdoptIQ ships with two operator-flippable model settings, persisted to settings.json (mode 0600, never committed):

ask_ai_model_name

Used by the Ask AI feature to answer portfolio queries. Faster models (e.g. gpt-4o-mini) give snappier replies; larger models (e.g. gpt-4o) reason more carefully on multi-customer portfolio prompts.

report_model_name

Used by every report generator (Compact, Comprehensive, Renewal, Leader, Subscription) for narrative paragraphs. Larger models reduce grounding-validator rejections on customer storyboards.

Both settings live behind their own panels on the analyze page. The flip is hot -- a new query / new analysis picks up the new model name on the very next call without needing a restart. Empty values fall back to the platform default. Malformed names (anything outside [A-Za-z0-9._-]) are rejected to prevent injection through the settings POST.

Quit AdoptIQ Cleanly

Use the Quit button in the navbar (or Quit AdoptIQ in the admin dashboard) instead of force-killing the process. The clean-quit path gives the app a chance to:

  • flush the in-memory analysis_status map back to disk so the next launch shows your prior runs in the History panel
  • scrub the in-memory plaintext knowledge corpus temp file (encrypted-at-rest contract)
  • refuse to quit while an analysis is still status='running' unless you confirm with Force quit
